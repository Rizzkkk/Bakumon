# Asset sourcing

Live coverage numbers are in `ground-truth/reports/asset-manifest.md`, regenerated by
`npm run mine`. This file explains where each class of image comes from and why.

## Pokemon artwork - PokeAPI

**904 of 904 species.** Official-artwork PNGs from `PokeAPI/sprites`, keyed on national
dex id, resolved from one bulk PokeAPI species request.

The Cobblemon wiki has **no** Pokemon pages or sprites, and the mod stores Pokemon art as
3D model texture atlases rather than portraits. ADR 0001 has the probe results.

Seven species are spelled two ways in the workbook (`hakamo_o` on row 410 and `hakamoo`
on row 411, each with its own spawn config) and neither spelling is PokeAPI's `hakamo-o`.
Underscore-to-hyphen recovers half; the rest are an explicit alias map in
`scripts/mine-assets.js`, because no rule derives `nidoranf` from `nidoran-f`.

## Item artwork - Cobblemon wiki first, mod asset tree second

**731 of 934 rows; 91% of rows that are actually items.**

1. **Cobblemon wiki** (615 files, CC BY 4.0). MediaWiki file pages are named after the
   item's display name - `File:Ability_Capsule.png`. Queried 50 titles per request, so
   934 items cost about 19 calls rather than 934 against a small community wiki that
   returned a live database error during the audit.
2. **Cobblemon mod asset tree** (116 files, MPL-2.0). Every Aprijuice variant, every
   ancient fishing rod and every stone ore is a real item with no wiki file page. The mod
   ships their textures, indexed once by filename across `item/`, `block/`, `berries/`,
   `fossils/` and `poke_balls/`. `item/` is searched first so a block's inventory icon
   wins over its world texture.

The 203 that resolve to nothing are mostly not items: 119 `poke_puff_overlay_*` GUI
sprites, 13 localisation fragments, 14 runtime-tinted Aprijuice variants, and a set of
Pokedex model-state textures. See `01-data/known-gaps.md`.

**155 recovered**, into `wiki_description`. The workbook leaves 548 of 932 items with no

## Thumbnails

Every downloaded image gets a WebP thumbnail:

- **Pokemon**: 256px, Lanczos. 904 full-size artwork files on one results grid is a real
  performance problem; the grid should use `thumb_url`.
- **Items**: 128px, **nearest neighbour**. These are 16x16 game textures. Any smooth
  resampling kernel turns crisp pixel art into mush.

## Re-running

`npm run mine` is resumable and idempotent. It reads `assets/manifest.json` first and
refetches only what is missing or failed, so a run that dies partway costs nothing.
`npm run mine items` or `npm run mine pokemon` does one half.

Rate limiting is per host, in `scripts/lib/fetch.js`: the wiki gets 2 concurrent requests
with a 400ms floor, CDNs get 8 and no delay. A response that arrives as HTML where an
image was expected is treated as a failure and retried - the wiki serves an HTML error
page with a 200 status when its database is down, which would otherwise land on disk as a
`.png` no decoder can open.
